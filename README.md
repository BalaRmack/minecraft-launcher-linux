# Horizon

Экспериментальный Minecraft-лаунчер для Linux на Rust, Tauri 2 и SQLite. Монохромный интерфейс на русском языке, без Electron. Проект ещё не является полноценным релизом: перед ежедневным использованием сохраните резервные копии миров и проверьте актуальные результаты CI.

## Возможности и их состояние

- Локальные офлайн-аккаунты: создание, редактирование, выбор, удаление и стабильный OfflinePlayer UUID. Это не замена Microsoft-авторизации: для официальных онлайн-серверов требуется лицензионный аккаунт.
- Изолированные сборки: версии release и snapshot из манифеста Mojang; Vanilla, Fabric, Quilt, Forge и NeoForge устанавливаются через встроенную копию `mc-launcher-core` 0.1.2. Мастер содержит собственный список версий с поиском, вкладками и подгрузкой; карточки показывают статус, версию и количество файлов модов, а управление вынесено на страницу сборки. Сборки можно переименовать, открыть их папку, удалить с подтверждением или скопировать целиком. Удаление удаляет **все** файлы сборки, включая миры.
- Перед отображением статуса и запуском проверяются метаданные, клиент, библиотеки, индекс и объекты ресурсов: известные контрольные суммы сверяются, файлы без хеша проверяются на наличие. Каталог нативных библиотек проверяется на наличие, но отдельные извлечённые файлы не сверяются. Для повреждённой или прерванной установки доступно восстановление. Отмена установки кооперативная: текущие сетевые запросы, установка Java или внешнего загрузчика могут завершаться не сразу. Прогресс показывает этап, число файлов и, где сервер сообщает размер, процент текущего файла, а не всей установки.
- В режиме `auto` выбирается системная Java подходящей основной версии; если её нет, загружается JRE Eclipse Temurin для Linux x86_64. Архив проверяется по SHA-256 из API Adoptium и распаковывается в пользовательский каталог приложения. Указанный вручную путь проверяется по требуемой версии. Настройки Java и памяти можно задать отдельно для каждой сборки или наследовать глобальные. Дополнительные аргументы JVM задаются по одному на строку и передаются без оболочки; размер окна также можно настроить отдельно. Установщики Forge/NeoForge получают тот же выбранный исполняемый файл Java.
- Игра запускается отдельным процессом с выбранным офлайн-аккаунтом и лимитом памяти; вывод пишется в журнал, завершение отображается в интерфейсе. Активную сборку нельзя удалить, скопировать или изменить во время игры или установки.
- Modrinth: каталог с поиском, сортировкой, фильтрами, страницами и кэшем ответов на 10 минут в памяти; просмотр полного текстового описания, автора и метаданных. Подбор версии по Minecraft и загрузчику, загрузка обязательных зависимостей, до четырёх параллельных асинхронных загрузок, повторное использование SHA-512 кэша между сборками, установка, включение/отключение и удаление файлов. Во вкладке «Мои моды» точные хеши сверяются с Modrinth: для распознанных файлов показываются несовместимые версии, объявленные конфликты и потенциально отсутствующие обязательные зависимости. Перед установкой также проверяются конфликты с распознанными включёнными модами. Неизвестные моды таким образом не проверяются; предупреждение об отсутствующей зависимости может появиться, если она установлена из другого источника. Удаление мода не удаляет зависимости автоматически.
- Загрузчик Minecraft одновременно выполняет до восьми независимых асинхронных загрузок в каждом этапе, использует временные файлы, проверку хешей, атомарное размещение и три попытки. Проверенные SHA-1/SHA-256 файлы копируются в общий кэш `downloads-cache` и повторно используются между изолированными сборками; изменения файлов одной сборки не меняют другие. Файлы без контрольной суммы загружаются повторно. В интерфейсе показываются количество завершённых и оставшихся файлов текущего этапа, средняя скорость этого этапа и прогресс текущего файла при известной длине. Количество файлов последующих этапов заранее неизвестно, поэтому общий процент всей установки не вычисляется. Прерванные файлы не возобновляются по HTTP Range.

**Не готово:** Microsoft OAuth и защищённое хранение токенов, скины, новости, полная проверка конфликтов произвольных локальных модов, безопасное обновление модов, CurseForge, импорт и экспорт сборок и модпаков, HTTP Range для возобновления прерванных загрузок, выбор каталога игры и управление кэшем. Java и загрузчики необходимо проверять на реальных версиях Minecraft; не предполагается, что все сочетания версий протестированы. При отключённой сети установка не работает; повторный запуск установленной игры не требует повторной установки (если Java уже присутствует).

Данные на обычном Linux хранятся в `$XDG_DATA_HOME/io.github.balarmack.horizon` (обычно `~/.local/share/io.github.balarmack.horizon`). При запуске игры в `game/horizon-game.log` записываются значения DISPLAY и WAYLAND_DISPLAY, наличие сокетов и DRI, а также раздел разрешений Flatpak; Xauthority и содержимое остальных переменных окружения не записываются. В Flatpak это пользовательский каталог внутри `~/.var/app/io.github.balarmack.horizon/`. Профили находятся в `instances/<UUID>`, игровые данные — в `game`, журнал вывода Java — в `game/horizon-game.log`. SQLite хранит профили и настройки, но не пароли или токены.

## Flatpak для Bazzite

Манифест выдаёт `--socket=x11` и `--socket=wayland`: Minecraft 1.10 использует LWJGL 2 и требует X11/XWayland даже когда окно лаунчера работает в Wayland. `fallback-x11` здесь не подходит, поскольку скрывает X11 при доступном Wayland. Для LWJGL 2 в Flatpak также включён официальный xrandr 1.5.4, необходимый для перечисления режимов экрана; на обычном Linux нужен установленный `xrandr`. Дополнительно разрешены `--share=ipc` и `--device=dri`; X11 даёт приложению широкий доступ к X-сессии. Подготовлены манифест и GitHub Actions workflow `Flatpak Linux`. Он собирает исходники офлайн внутри GNOME SDK 50 из предварительно скачанных Cargo-зависимостей, создаёт `horizon.flatpak`, устанавливает его и проверяет запуск `--version` в sandbox. Также настроены запуск окна и тест Java, Vanilla 1.10 и 1.20.1, Fabric и модов в sandbox под Xvfb без принудительного добавления X11-разрешения в команде теста. Смотрите результат каждого задания для конкретного коммита: такая проверка не равнозначна тестированию на Bazzite и реальном GPU. Доступы ограничены сетью, Wayland/X11, графикой, аудио и IPC; доступ ко всему домашнему каталогу не выдаётся.

Если workflow **успешно завершился** и в нём опубликован артефакт `horizon-flatpak-x86_64`, скачайте и распакуйте его из GitHub Actions. На Bazzite установите Flathub, если он ещё не добавлен, а затем пакет:

```sh
flatpak remote-add --user --if-not-exists flathub https://dl.flathub.org/repo/flathub.flatpakrepo
flatpak install --user ./horizon.flatpak
flatpak run io.github.balarmack.horizon
```

При первой установке потребуется загрузить GNOME runtime с Flathub; файлы игры и Java загружаются при установке сборки. RPM-пакеты хоста не нужны. До успешной сборки и испытания на Bazzite нельзя считать этот пакет готовым к ежедневной эксплуатации.

Для разработчиков: `packaging/flatpak/build.sh` требует `cargo`, `flatpak`, `flatpak-builder`, настроенный пользовательский remote `flathub` и сетевой доступ при подготовке Cargo vendor. Он генерирует временный исходный каталог `.flatpak-source`, собирает его в sandbox и создаёт `horizon.flatpak`. Зависимости Rust зафиксированы в `src-tauri/Cargo.lock`; SDK и CI-окружение всё ещё необходимо контролировать отдельно для побитовой воспроизводимости.

## Сборка для разработки на Debian/Ubuntu x86_64

```sh
sudo apt-get update
sudo apt-get install build-essential libwebkit2gtk-4.1-dev libxdo-dev libssl-dev librsvg2-dev liblzma-dev patchelf
npm ci
npm test
cargo test --manifest-path src-tauri/Cargo.toml
npx --yes @tauri-apps/cli@2 dev
npx --yes @tauri-apps/cli@2 build --bundles deb
```

`.deb` предназначен для Debian/Ubuntu, не для установки на Bazzite. Для тестирования с реальной сетью, X11 и OpenGL подготовлен отдельный игнорируемый Rust-тест `live_minecraft_vanilla_and_fabric`: он загружает управляемую Java 8 и 17, проверяет Minecraft 1.10 и 1.20.1, повторную установку, общий кэш, Fabric, Sodium и Lithium и запускает игры под виртуальным дисплеем. Для 1.10 он ожидает загрузку ресурсов после инициализации дисплея; для 1.20.1 — инициализацию LWJGL. На Linux с Xvfb:

```sh
xvfb-run -a -s '-screen 0 1280x720x24' cargo test --manifest-path src-tauri/Cargo.toml live_minecraft_vanilla_and_fabric -- --ignored --nocapture
```

Время Java и установки модов в таблицу не входит; 1.20.1 частично использует кэш, оставшийся от теста 1.10. Счётчики относятся к заданиям файлов на этапах и могут повторять один и тот же файл в разных этапах. Скорости включают время проверки и локальной записи, зависят от сети и диска runner и не являются прогнозом для Bazzite. Нативный тест и Flatpak-тест не являются проверкой игры на реальном GPU или в пользовательской сессии Wayland.

Тест загружает сотни мегабайт и требует доступ к Mojang, Adoptium и Fabric. Текущий тест дополнительно устанавливает Sodium из Modrinth перед запуском Fabric; он не проверяет все зависимости модов, Microsoft OAuth или Bazzite sandbox. Отдельные unit-тесты не подменяют реальную сетевую интеграцию. Состояние проверок — в GitHub Actions для конкретного коммита.

Копия `mc-launcher-core` лицензирована MIT; исходная лицензия и README находятся в `src-tauri/vendor/mc-launcher-core`. Minecraft является товарным знаком Mojang Studios; Horizon не является официальным продуктом Minecraft.

### Смена загрузчика и прогресс установки

В настройках сборки выберите «Изменить загрузчик»: Horizon предложит доступные версии из официальных метаданных, проверит распознанные Modrinth моды и после подтверждения создаст отдельную копию и установит выбранный загрузчик. Исходная сборка не изменяется; миры, моды и настройки копируются. Неизвестные Modrinth файлы нельзя автоматически проверить на совместимость, поэтому перед запуском новой копии проверьте их вручную. Символические ссылки и специальные файлы в сборке останавливают копирование, а не копируются с риском потери данных. При ошибке установки копия остаётся для повторной установки; оригинал сохраняется. Не изменяйте игровые файлы внешними программами во время копирования.

Общий план установки заранее неизвестен (в том числе работа установщиков Forge/NeoForge и Java), поэтому общая полоса неопределённая, а не поддельный процент. Доступный процент относится к текущему файлу; число завершённых и оставшихся относится к текущему этапу. Счётчики скачанных и повторно использованных файлов отражают операции загрузчика, включая повторные этапы; в повторное использование входят как локальные файлы, так и кэш. Скорость рассчитывается по поступившим событиям, за последний интервал отображения, и не включает отдельные загрузки Java и внешних установщиков. ETA не показывается без достоверного общего объёма. Отмена кооперативна: активный внешний установщик или установка Java могут сначала завершиться.

### Состояние модов в каталоге

Каталог проверяет файлы выбранной сборки по SHA-512, а не по имени: для установок Horizon соответствие хеша, проекта и версии дополнительно сохраняется в `.horizon-modrinth.json` рядом с папкой `mods`. Ручные файлы распознаются по хешу Modrinth; для Fabric/Quilt также учитывается явная ссылка на проект Modrinth в метаданных JAR. В последнем случае версия Modrinth может остаться неизвестной. Отключённые моды тоже считаются имеющимися файлами. Если остались неопознанные файлы или проверка недоступна, состояние остальных проектов неизвестно, и установка блокируется, чтобы не создать дубликат. Проверяйте такие файлы в «Моих модах».

Обновление предлагается только при подтверждённой более новой версии, совместимой с Minecraft и загрузчиком сборки. Старый файл сохраняется в `game/.horizon-mod-backups/`, новая версия проверяется по SHA-512 до замены. Обновление может быть остановлено при конфликте зависимостей или нескольких файлах одного проекта; неизвестные зависимости вручную добавленных модов автоматически не выявляются.

### Описания модов и безопасность

Окно описания загружает сведения только выбранного проекта. Markdown (включая таблицы и код) разбирается в Web Worker, результат кэшируется в памяти и по частям очищается DOMPurify перед показом. Описание длиннее 600 000 символов обрезается с уведомлением. Изображения подгружаются по мере приближения к видимой области; внешние HTTPS-изображения могут раскрывать IP-адрес пользователю соответствующего сервера. Видеовставки YouTube и Vimeo загружаются только по нажатию, в sandbox; другие iframe не запускаются. Внешние ссылки открываются в системном браузере. Разрешена только безопасная HTTPS-схема; скрипты, события HTML и небезопасные элементы удаляются.

Интерфейс поддерживает уменьшение анимации через системный `prefers-reduced-motion`. Проверка интерфейса `npm test` использует jsdom; дополнительный `tests/browser-ui.cjs` измеряет поведение длинного описания в headless Chromium в Linux CI. Это не заменяет профилирование GTK WebKit или проверку плавности на реальном GPU/дисплее.
