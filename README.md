# Horizon

Экспериментальный Minecraft-лаунчер для Linux на Rust, Tauri 2 и SQLite. Монохромный интерфейс на русском языке, без Electron. Проект ещё не является полноценным релизом: перед ежедневным использованием сохраните резервные копии миров и проверьте актуальные результаты CI.

## Возможности и их состояние

- Локальные офлайн-аккаунты: создание, редактирование, выбор, удаление и стабильный OfflinePlayer UUID. Это не замена Microsoft-авторизации: для официальных онлайн-серверов требуется лицензионный аккаунт.
- Изолированные сборки: версии release и snapshot из манифеста Mojang; Vanilla, Fabric, Quilt, Forge и NeoForge устанавливаются через встроенную копию `mc-launcher-core` 0.1.2. Мастер содержит собственный список версий с поиском, вкладками и подгрузкой; карточки показывают дату последнего запуска и количество файлов модов. Сборки можно переименовать, открыть их папку, удалить с подтверждением или скопировать целиком. Удаление удаляет **все** файлы сборки, включая миры.
- В режиме `auto` выбирается системная Java подходящей основной версии; если её нет, загружается JRE Eclipse Temurin для Linux x86_64. Архив проверяется по SHA-256 из API Adoptium и распаковывается в пользовательский каталог приложения. Указанный вручную путь проверяется по требуемой версии. Настройки Java и памяти можно задать отдельно для каждой сборки или наследовать глобальные. Установщики Forge/NeoForge получают тот же выбранный исполняемый файл Java.
- Игра запускается отдельным процессом с выбранным офлайн-аккаунтом и лимитом памяти; вывод пишется в журнал, завершение отображается в интерфейсе. Активную сборку нельзя удалить, скопировать или изменить во время игры или установки.
- Modrinth: каталог с поиском, сортировкой, фильтрами, страницами и кэшем ответов на 10 минут в памяти; просмотр полного текстового описания, автора и метаданных. Подбор версии по Minecraft и загрузчику, загрузка обязательных зависимостей, SHA-512, установка, включение/отключение и удаление файлов. Во вкладке «Мои моды» точные хеши сверяются с Modrinth: для распознанных файлов показываются несовместимые версии, объявленные конфликты и потенциально отсутствующие обязательные зависимости. Перед установкой также проверяются конфликты с распознанными включёнными модами. Неизвестные моды таким образом не проверяются; предупреждение об отсутствующей зависимости может появиться, если она установлена из другого источника. Удаление мода не удаляет зависимости автоматически.
- Загрузчик ядра использует временные файлы, проверку доступных хешей, атомарное размещение и три попытки. Файлы без известной контрольной суммы загружаются повторно. Процентный прогресс недоступен, отображаются текущие этапы. Скачивание остаётся последовательным; библиотеки и ресурсы хранятся отдельно для каждой сборки.

**Не готово:** Microsoft OAuth и защищённое хранение токенов, скины, новости, полная проверка конфликтов произвольных локальных модов, безопасное обновление модов, CurseForge, импорт и экспорт сборок и модпаков, параллельные загрузки, выбор каталога игры, настройки JVM-аргументов и управление кэшем. Java и загрузчики необходимо проверять на реальных версиях Minecraft; не предполагается, что все сочетания версий протестированы. При отключённой сети установка не работает; повторный запуск установленной игры не требует повторной установки (если Java уже присутствует).

Данные на обычном Linux хранятся в `$XDG_DATA_HOME/io.github.balarmack.horizon` (обычно `~/.local/share/io.github.balarmack.horizon`). В Flatpak это пользовательский каталог внутри `~/.var/app/io.github.balarmack.horizon/`. Профили находятся в `instances/<UUID>`, игровые данные — в `game`, журнал вывода Java — в `game/horizon-game.log`. SQLite хранит профили и настройки, но не пароли или токены.

## Flatpak для Bazzite

Подготовлены манифест и GitHub Actions workflow `Flatpak Linux`. Он собирает исходники офлайн внутри GNOME SDK 50 из предварительно скачанных Cargo-зависимостей, создаёт `horizon.flatpak`, устанавливает его и проверяет запуск `--version` в sandbox. Для следующих сборок также настроены запуск окна и тест Java, Vanilla, Fabric и Sodium в sandbox под Xvfb. Смотрите результат каждого задания для конкретного коммита: такая проверка не равнозначна тестированию на Bazzite и реальном GPU. Доступы ограничены сетью, Wayland/X11, графикой, аудио и IPC; доступ ко всему домашнему каталогу не выдаётся.

Если workflow **успешно завершился** и в нём опубликован артефакт `horizon-flatpak-x86_64`, скачайте и распакуйте его из GitHub Actions. На Bazzite установите Flathub, если он ещё не добавлен, а затем пакет:

```sh
flatpak remote-add --user --if-not-exists flathub https://dl.flathub.org/repo/flathub.flatpakrepo
flatpak install --user ./horizon.flatpak
flatpak run io.github.balarmack.horizon
```

При первой установке потребуется загрузить GNOME runtime с Flathub; файлы игры и Java загружаются при установке сборки. RPM-пакеты хоста не нужны. До успешной сборки и испытания на Bazzite нельзя считать этот пакет готовым к ежедневной эксплуатации.

Для разработчиков: `packaging/flatpak/build.sh` требует `cargo`, `flatpak`, `flatpak-builder`, настроенный пользовательский remote `flathub` и сетевой доступ при подготовке Cargo vendor. Он генерирует временный исходный каталог `.flatpak-source`, собирает его в sandbox и создаёт `horizon.flatpak`. Зависимости Rust зафиксированы в `src-tauri/Cargo.lock`; SDK и CI-окружение всё ещё необходимо контролировать отдельно для побитовой воспроизводимости.

## Сборка для разработки на Debian/Ubuntu x86_64

```sh
sudo apt-get update
sudo apt-get install build-essential libwebkit2gtk-4.1-dev libxdo-dev libssl-dev librsvg2-dev liblzma-dev patchelf
npm ci
npm test
cargo test --manifest-path src-tauri/Cargo.toml
npx --yes @tauri-apps/cli@2 dev
npx --yes @tauri-apps/cli@2 build --bundles deb
```

`.deb` предназначен для Debian/Ubuntu, не для установки на Bazzite. Для тестирования с реальной сетью, X11 и OpenGL подготовлен отдельный игнорируемый Rust-тест `live_minecraft_vanilla_and_fabric`: он принудительно загружает управляемую Java и Minecraft 1.20.1, проверяет повторное использование файлов, устанавливает Fabric и ожидает инициализацию LWJGL у обеих версий. На Linux с Xvfb:

```sh
xvfb-run -a -s '-screen 0 1280x720x24' cargo test --manifest-path src-tauri/Cargo.toml live_minecraft_vanilla_and_fabric -- --ignored --nocapture
```

На коммите `81bdb1d` [нативный CI](https://github.com/BalaRmack/minecraft-launcher-linux/actions/runs/44889990103) успешно прошёл этот тест с принудительной загрузкой Java, Vanilla, Fabric, Sodium и повторным использованием файлов. Он проверяет достижение инициализации LWJGL, но не ручную игру. [Сборка Flatpak коммита `81bdb1d`](https://github.com/BalaRmack/minecraft-launcher-linux/actions/runs/44889990074) также прошла установку, запуск окна и тот же тест игры внутри sandbox под Xvfb; артефакт `horizon-flatpak-x86_64` доступен в этом запуске, но старее текущего кода. Это не проверка на Bazzite или на реальном GPU.

Тест загружает сотни мегабайт и требует доступ к Mojang, Adoptium и Fabric. Текущий тест дополнительно устанавливает Sodium из Modrinth перед запуском Fabric; он не проверяет все зависимости модов, Microsoft OAuth или Bazzite sandbox. Отдельные unit-тесты не подменяют реальную сетевую интеграцию. Состояние проверок — в GitHub Actions для конкретного коммита.

Копия `mc-launcher-core` лицензирована MIT; исходная лицензия и README находятся в `src-tauri/vendor/mc-launcher-core`. Minecraft является товарным знаком Mojang Studios; Horizon не является официальным продуктом Minecraft.
